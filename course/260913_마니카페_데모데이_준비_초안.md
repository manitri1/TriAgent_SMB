# 마니카페 데모데이 준비 초안

**출처**: `course/assets/09_260913일_교안.pdf` 28~38페이지("시연 영상 제작"~"멘토링 기간 실행 계획") 워크숍 산출물의 초안. 완성본이 아니라 멘토링 기간에 다듬을 초안 상태다("완성도보다 존재 여부가 기준").

**전제 사실** — 이 초안은 실제 마니카페(TriAgent_SMB) 프로젝트 상태를 근거로 썼다: coordinator + 전문 에이전트 6개, HITL 승인 게이트 3종(프로모션 집행 / 대량 발주 15만원 상한 / 결제·환불), mock-pos API, 운영 콘솔 웹앱(주문 접수·재고 관리·고객 문의·예약 관리·대시보드 + 손님용 미리보기·라이브 데모). 자세한 근거는 [260911_마니카페_MVP_계획서_갱신판.md](260911_마니카페_MVP_계획서_갱신판.md) 참고.

## 1. 시연 영상 장면 구성 (교안 p.29)

**총 러닝타임 2분(120초) 이내가 하드 제약**. 소리 없이도 이해 가능, 자막 필수, 실화면 사용(기획안 화면 아님). `/live-demo`(사장님 라이브 데모, 12장면)의 실제 응답 대기는 화면에 적힌 대로 "보통 25초~4분"이라 그대로 녹화하면 예산을 넘긴다 — 반드시 **"전송 클릭 → 대기 컷 → 완료된 결과 화면"** 순서로 편집(또는 미리 완료된 상태를 녹화)해서, 대기 시간 자체는 화면에 담지 않는다.

| 장면 | 길이 | 내용 |
|---|---|---|
| 장면 1 | 10초 | 오프닝. 운영 콘솔 홈 화면(`/home`)에서 시작. 자막: "마니카페 — 사장님 혼자서도 돌아가는 카페 운영 콘솔" |
| 장면 2 | 15초 | 문제 제시. `/live-demo` "재고 스냅샷" 결과 — 아메리카노 재고 위험 상태 노출. 자막: "1인 사장님은 재고·주문·문의를 혼자 확인해야 한다" |
| 장면 3 | 25초 | 핵심 조작① HITL 게이트. `/live-demo` "[게이트2] 결품 발견 + 발주 초안" — 보내기 클릭 → (컷) → HITL 확인 카드(진행 카드 + 수량/범위 선택 칩) 노출, "50개로 진행" 칩 클릭. 자막: "AI가 마음대로 발주하지 않는다" |
| 장면 4 | 25초 | 핵심 조작② 실결제 반영. `/live-demo` "[게이트3] 결제/환불" — 보내기 → (컷) → mock-pos 매출에 실제 반영된 결과 패널 |
| 장면 5 | 15초 | 결과 확인. 대시보드로 이동해 매출과 "사장님이 오늘 확인해야 할 것" 카드가 갱신된 화면 |
| 장면 6 | 10초 | 클로징. 배포 주소 자막 + "한 매장의 반복 업무 자동화에서, 여러 매장의 데이터를 함께 쌓는 방향으로 확장합니다" |

합계 100초(1분 40초) — 자막 타이밍·전환 컷 여유로 20초를 남겨둔다.

**주의**: 설정/회원가입/관리자 화면은 시연 대상에서 제외, 시연 계정으로 로그인된 상태에서 시작, 시연용 샘플 데이터 미리 입력(빈 목록 노출 금지). 장면 3의 HITL 카드는 실제 coordinator 응답에서 파싱되므로, 녹화 전에 재고를 실제로 품절/위험 상태로 맞춰 리허설로 한 번 확인해둘 것.

## 2. 발표 슬라이드 뼈대 (교안 p.31)

| 장 | 핵심 문장(초안) |
|---|---|
| 표지 | 마니카페 — 사장님 혼자서도 돌아가는 카페 운영 콘솔 |
| 문제 | 1인·소수 인력 카페 사장님은 주문·재고·고객 문의·예약을 전부 혼자 확인하며, 그중 결제·환불·대량 발주처럼 돈이 오가는 결정도 놓치기 쉽다 |
| 해결 | coordinator 에이전트가 6개 전문 에이전트(주문/결제·재고·고객문의·예약·매출분석·마케팅)에게 위임해 하나의 콘솔에서 처리하고, 결제·환불·15만원 이상 발주는 반드시 사장님 승인을 거친다 |
| 시연 | (영상 재생 — 위 6장면, 100초) |
| 증거 | mock-pos API·pytest 전량 통과, 웹앱 테스트 87건 통과, 카푸치노 1잔 주문 접수→결제 완료 e2e 3분 39초 실측, 컨테이너 2일 이상 실가동 |
| 차별점 | 데이터 축적(매장별 운영 데이터가 대시보드 인사이트로 쌓임) · 전환 비용(사장님 일일 루틴에 이미 붙은 콘솔+승인 흐름) · 브랜드 신뢰(HITL 3종 게이트로 "AI가 마음대로 결제·발주하지 않는다"는 확인 가능한 안전장치) — **유통 접근은 아직 약한 지점, 정직하게 계획 장에서 다룬다** |
| 계획 | Discord 실알림 발송 검증, 3개 미실행 에이전트(예약/매출분석/마케팅) 단독 스모크 테스트, 이후 업종 확장(식당 등) — 사업화 지원 신청 시 이 순서로 사용 |
| 마무리 | 연락처 + 배포 링크(`smb-webapp.srv1923951.hstgr.cloud`, 계정 필요) |

## 3. 심사에서 반복되는 질문 — 사전 답변 초안 (교안 p.32)

슬라이드 안에 미리 배치하는 걸 권장하므로("질의응답보다 발표 안에 미리 배치하는 편이 유리"), 답이 약한 항목은 지금 정직하게 표시해둔다.

| 질문 | 답변 초안 |
|---|---|
| 결제 주체 | 카페 사장님(운영자)이 비용을 지불하는 구조를 가정 — **구체적 가격정책은 아직 미정, 사업화 계획에서 보완 필요** |
| 사용 증거 | 실제 카페(마니카페 연남점) 운영값을 반영한 발주 상한 15만원, 컨테이너 2일 이상 실가동, pytest 자동검증 전량 통과 |
| 대체 수단 | 기존엔 전화·카카오톡 문의 + 수기 재고 확인 + 별도 POS를 오가며 처리 — 마니카페는 하나의 승인 흐름 안에서 확인부터 처리, 결과 확인까지 끝난다 |
| 지속 가능성 | 운영 비용은 LLM API 호출 + VPS 호스팅 — 현재는 자비 부담, **구독료로 회수하는 모델은 아직 설계 전** |
| 차별점 | 동일한 기능의 서비스가 등장해도 남는 것은 이 매장에 쌓인 운영 데이터와, 사장님이 이미 익힌 승인 흐름(전환 비용) |
| 실행 계획 | 지원을 받으면 Discord 알림 실연동, 외부 결제 API(토스플레이스) 계약, 업종 확장 검증에 사용 |

## 4. 발표 자가 점검 (교안 p.37) — 현재 상태 기준 초안

| 항목 | 자가 평가 |
|---|---|
| 문제 정의 | 보통 — 대상은 명확(1인·소수 인력 카페 사장님)하나, 매장 규모·인력 조건을 더 구체화하면 좋다 |
| 고객과 결제 | **미흡 — 최저 항목**. 사용자(사장님)는 명확하나 비용 지불 조건이 미정 |
| 시연 완성도 | 양호 — 핵심 경로(주문 접수→결제, 재입고 승인)는 e2e 검증됨. 단, 최근 화면 리팩터링 중이라 시연 전 재검증 필요 |
| 실사용 증거 | 양호 — pytest 자동검증, 실측 처리시간 존재 |
| 사업화 계획 | 미흡 — 수익 구조 초안이 없음 |
| 전달력 | 검증 전 — 리허설로 시간·이해도 확인 필요 |

**최저 항목(멘토링 기간 최우선 과제): 고객과 결제 — 가격정책/수익구조 초안 작성**

## 5. 멘토링 기간 실행 계획 (교안 p.38)

| 구분 | 항목 |
|---|---|
| 할 일 세 개 | ① 자가점검 최저 항목 보완 — 가격정책/수익구조 초안 작성 ② 시연 영상 최종본 완성(위 6장면·100초 기준 실제 녹화, 대기 시간은 컷 편집) ③ 발표 슬라이드 채우고 시간 측정 리허설 |
| 하지 않을 일 | 신규 기능 추가 / 디자인 전면 수정 / 기술 스택 교체 / 새 도구 도입 실험 |
| 제출 마감 | **목요일 16시 — 마감 이후 자료 교체 불가** |

체크리스트: 할 일 세 개를 실행 가능한 크기로 기재했는가 / 막힘 발생 시 요청할 멘토를 미리 지정했는가 / 각 항목의 완료 시점을 마감 이전으로 배치했는가 / 제출 항목 네 가지(시연 시나리오 대본·시연 영상·발표 슬라이드·실행 계획)를 마감 전날까지 확보했는가.
