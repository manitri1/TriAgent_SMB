# 마니카페 데모데이 준비 초안

**출처**: `course/assets/09_260913일_교안.pdf` 28~38페이지("시연 영상 제작"~"멘토링 기간 실행 계획") 워크숍 산출물의 초안. 완성본이 아니라 멘토링 기간에 다듬을 초안 상태다("완성도보다 존재 여부가 기준").

**전제 사실** — 이 초안은 실제 마니카페(TriAgent_SMB) 프로젝트 상태를 근거로 썼다: coordinator + 전문 에이전트 6개, HITL 승인 게이트 3종(프로모션 집행 / 대량 발주 15만원 상한 / 결제·환불), mock-pos API, 운영 콘솔 웹앱(주문 접수·재고 관리·고객 문의·예약 관리·대시보드 + 손님용 미리보기·라이브 데모). 자세한 근거는 [260911_마니카페_MVP_계획서_갱신판.md](260911_마니카페_MVP_계획서_갱신판.md) 참고.

## 1. 시연 영상 장면 구성 (교안 p.29, 2026-09-15 갱신 — 화면·버튼·결과 확인 방법을 클릭 단위로 구체화)

**총 러닝타임 2분(120초) 이내가 하드 제약**. 소리 없이도 이해 가능, 자막 필수, 실화면 사용(기획안 화면 아님). `/live-demo`(사장님 라이브 데모, 12장면)의 실제 응답 대기는 화면에 적힌 대로 "보통 25초~4분"이라 그대로 녹화하면 예산을 넘긴다 — 반드시 **"전송 클릭 → 대기 컷 → 완료된 결과 화면"** 순서로 편집(또는 미리 완료된 상태를 녹화)해서, 대기 시간 자체는 화면에 담지 않는다. 장면 1~4·6은 `/live-demo`, 장면 5·7은 실제 운영 화면 `/dashboard`를 사용한다(마케팅·CRM 제안 팝업은 `/live-demo` 스토리보드가 아니라 대시보드 자체 기능이라 화면 전환이 필요하다).

> **녹화 전 필수 준비(2026-09-15 추가 기능)**: `/dashboard`의 **"목업 데이터 초기 세팅"** 버튼으로 아래 시연에 필요한 데이터 상태를 한 번에 만들 수 있다.
> - 장면 2·3(아메리카노 품절 노출)에는 **"빠르게 채우기"** 모드를 쓴다 — 아메리카노 재고가 0으로 세팅된다.
> - 장면 5·6(VIP 단골 카드, "확인해야 할 것" 카드 다양성)에는 **"한 달 시뮬레이션"** 모드를 쓴다 — 재방문 고객·재고 위험/부족·소진 임박·이탈 위험 단골·오늘 예약까지 서로 다른 카드가 최소 4~5개, 오늘 매출도 0이 아닌 실제 값으로 채워지도록 자동 보정된다(예전에는 이 조건들이 우연에 맡겨져 있었다).
> - 두 모드 모두 **기존 데이터를 지우므로**, 촬영 순서상 장면 2·3을 먼저 찍고 "빠르게 채우기"로 리셋 → 장면 5·6을 위해 "한 달 시뮬레이션"으로 다시 세팅 → 이후 장면 4(결제)는 "한 달 시뮬레이션" 상태에서 찍어도 무방하다(신규 주문 자체는 어떤 시드 상태에서도 정상 동작).

합계 110초(1분 50초) — 자막 타이밍·전환 컷 여유로 10초를 남겨둔다.

**주의**: 설정/회원가입/관리자 화면은 시연 대상에서 제외, 시연 계정으로 로그인된 상태에서 시작, 시연용 샘플 데이터 미리 입력(빈 목록 노출 금지). 장면 3의 HITL 카드는 실제 coordinator 응답에서 파싱되므로, 녹화 전에 재고를 실제로 품절/위험 상태로 맞춰(위 "목업 데이터 초기 세팅 → 빠르게 채우기") 리허설로 한 번 확인해둘 것.

**이번에 보완한 부분(기존 안에서 빠져 있던 것)**:
1. **장면 1 진입 경로 누락** — 로그인 직후 기본 화면은 `/home`이 아니라 `/dashboard`다(`webapp_bff/routers/pages.py`의 `/` 리다이렉트). `/home`으로 가려면 상단 "사용자 ▾" 드롭다운에서 "사장님 화면"을 눌러야 한다는 조작이 빠져 있었다 — 표에 추가했다.
2. **장면 2가 "전송" 조작으로 오인될 여지** — 실제 `/live-demo`의 06:30 장면은 `type: "link"`(읽기 전용)이라 채팅 입력창·보내기 버튼 자체가 없다. 클릭 한 번으로 결과 패널만 자동으로 뜬다는 점을 명확히 했다.
3. **장면 3의 "두 번째 대기"가 누락** — 칩을 클릭하면 그 자체로 또 한 번 coordinator 호출이 발생해 25초~4분이 걸린다(원래 표는 마치 칩 클릭이 곧바로 장면을 끝내는 것처럼 보였다). 두 번째 대기까지 실시간으로 담지 않아도 된다는 점과 그 이유를 명시했다.
4. **결과 확인 방법이 화면 동작 서술에 섞여 있어 불명확** — "무엇이 보이면 성공인지"를 장면별로 별도 열로 분리했다(재고 0, 완료 pill, "완료 —" 텍스트, 카드 개수, 매출 0원 아님 등 구체적 판정 기준).
5. **장면 5·2·3의 전제 데이터가 "확인만" 권장되고 준비 방법은 없었음** — 지난 대화에서 만든 "목업 데이터 초기 세팅" 버튼(빠르게 채우기/한 달 시뮬레이션)을 촬영 순서까지 포함해 구체적인 준비 절차로 연결했다.
6. **장면 5의 "초안 작성 완료"는 실제로 뜨는 고정 문구가 아니었음** — 마케팅 제안 결과 텍스트는 marketing-crm-agent의 실제 응답을 그대로 보여주므로 호출마다 문구가 다르다. "완료" 같은 고정 접두어를 찾도록 편집 가이드를 짜면 리허설 때 당황할 수 있어, 판정 기준을 "결과 박스 색상이 대기→완료 스타일로 바뀌는지"로 바로잡았다.

## 2. 발표 슬라이드 뼈대 (교안 p.31)

| 장 | 핵심 문장(초안) |
|---|---|
| 표지 | 마니카페 — 사장님 혼자서도 돌아가는 카페 운영 콘솔 |
| 문제 | 1인·소수 인력 카페 사장님은 주문·재고·고객 문의·예약을 전부 혼자 확인하며, 그중 결제·환불·대량 발주처럼 돈이 오가는 결정도 놓치기 쉽다 |
| 해결 | coordinator 에이전트가 6개 전문 에이전트(주문/결제·재고·고객문의·예약·매출분석·마케팅)에게 위임해 하나의 콘솔에서 처리하고, 결제·환불·15만원 이상 발주는 반드시 사장님 승인을 거친다 |
| 시연 | (영상 재생 — 위 7장면, 110초) |
| 증거 | 자동화 테스트 123건 전량 통과(웹앱 98건 + mock-pos 25건, 2026-09-14 기준), 카푸치노 1잔 주문 접수→결제 완료 e2e 3분 39초 실측, 대시보드 "마케팅·CRM 제안" 클릭 → coordinator 경유 초안 완료까지 실동작 검증, 배포마다 자동 테스트 전량 통과 확인 후 반영 |
| 차별점 | 데이터 축적(매장별 운영 데이터가 대시보드 인사이트로 쌓임) · 전환 비용(사장님 일일 루틴에 이미 붙은 콘솔+승인 흐름) · 브랜드 신뢰(HITL 3종 게이트로 "AI가 마음대로 결제·발주하지 않는다"는 확인 가능한 안전장치) — **유통 접근은 아직 약한 지점, 정직하게 계획 장에서 다룬다** |
| 계획 | Discord 실알림 발송 검증, 3개 미실행 에이전트(예약/매출분석/마케팅) 단독 스모크 테스트, 이후 업종 확장(식당 등) — 사업화 지원 신청 시 이 순서로 사용 |
| 마무리 | 연락처 + 배포 링크(`smb-webapp.srv1923951.hstgr.cloud`, 계정 필요) |

## 3. 심사에서 반복되는 질문 — 사전 답변 초안 (교안 p.32)

슬라이드 안에 미리 배치하는 걸 권장하므로("질의응답보다 발표 안에 미리 배치하는 편이 유리"), 답이 약한 항목은 지금 정직하게 표시해둔다.

| 질문 | 답변 초안 |
|---|---|
| 결제 주체 | 카페 사장님(운영자)이 비용을 지불하는 구조를 가정 — **구체적 가격정책은 아직 미정, 사업화 계획에서 보완 필요** |
| 사용 증거 | 실제 카페(마니카페 연남점) 운영값을 반영한 발주 상한 15만원, 자동화 테스트 123건(웹앱 98 + mock-pos 25) 전량 통과, 배포마다 재검증 후 반영 |
| 대체 수단 | 기존엔 전화·카카오톡 문의 + 수기 재고 확인 + 별도 POS를 오가며 처리 — 마니카페는 하나의 승인 흐름 안에서 확인부터 처리, 결과 확인까지 끝난다 |
| 지속 가능성 | 운영 비용은 LLM API 호출 + VPS 호스팅 — 현재는 자비 부담, **구독료로 회수하는 모델은 아직 설계 전** |
| 차별점 | 동일한 기능의 서비스가 등장해도 남는 것은 이 매장에 쌓인 운영 데이터와, 사장님이 이미 익힌 승인 흐름(전환 비용) |

## 4. 발표 자가 점검 (교안 p.37) — 현재 상태 기준 초안

| 항목 | 자가 평가 |
|---|---|
| 문제 정의 | 보통 — 대상은 명확(1인·소수 인력 카페 사장님)하나, 매장 규모·인력 조건을 더 구체화하면 좋다 |
| 고객과 결제 | **미흡 — 최저 항목**. 사용자(사장님)는 명확하나 비용 지불 조건이 미정 |
| 시연 완성도 | 양호 — 핵심 경로(주문 접수→결제, 재입고 승인)는 e2e 검증됨. 운영 화면 4개(문의·주문·재고·예약)의 목록·채팅 UI 재구성과 대시보드 마케팅·CRM 제안 기능은 2026-09-14 재배포 후 자동 테스트·Playwright로 재검증 완료. 남은 건 위 7장면 대본 기준 실제 녹화 리허설 |
| 실사용 증거 | 양호 — pytest 자동검증, 실측 처리시간 존재 |
| 사업화 계획 | 미흡 — 수익 구조 초안이 없음 |
| 전달력 | 검증 전 — 리허설로 시간·이해도 확인 필요 |

**최저 항목(멘토링 기간 최우선 과제): 고객과 결제 — 가격정책/수익구조 초안 작성**
