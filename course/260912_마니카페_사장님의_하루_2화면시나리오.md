## 두 개의 화면

| 화면 | 보는 사람 | 웹앱 매핑 |
|---|---|---|
| **손님용 화면** | 카페를 찾은 손님, 전화·문자로 문의하는 손님 | `/support`(문의·컴플레인), `/orders`(주문·결제), `/reservations`(예약) 의 손님 접점 부분, 매장 메뉴판 |
| **매장 대시보드** | 사장님 | `/dashboard`, `/inventory`, mock-pos 대시보드(`:18080/dashboard`), Hermes 대시보드(`:19128`)의 `/chat`, Discord `#smb-ops` |

같은 시각, 같은 사건이 두 화면에 서로 다른 모습으로 나타납니다. 손님은 자신의 요청이 어떻게 처리되는지를 손님용 화면에서 확인하고, 사장님은 대시보드에서 전체 흐름과 승인 요청을 확인합니다. 각 접점은 아래 세 단계로 구성됩니다.

- **① 액션** — 손님(또는 상황)이 만들어내는 입력. 전화·음성처럼 화면이 없는 접점은 "화면 없음"으로 표시합니다(구현 범위는 문서 끝 참고 참조).
- **② 결과 표시** — 그 액션이 손님용 화면과 매장 대시보드 각각에 무엇으로 나타나는지.
- **③ 다음 액션** — 그 결과를 보고 손님 쪽과 사장님(또는 에이전트) 쪽이 각각 무엇을 하는지. 승인이 필요한 접점은 대시보드 쪽 다음 액션이 "🔒 승인 대기 → 사장님 승인/반려"로 멈춥니다.

## 같은 하루, 두 화면으로 본 부담의 이동

기존 방식에서는 손님용 화면과 매장 대시보드의 구분 자체가 없었습니다 — 사장님이 전화를 받고, 카운터를 보고, 수첩에 재고를 적는 모든 행위가 한 사람 안에서 일어났습니다. AI 에이전트 방식에서는 손님의 액션이 각 전담 에이전트를 거쳐 대시보드에 결과로 먼저 쌓이고, **돈이 오가거나 손님에게 나가는 3곳(🔒 발주·🔒 결제/환불·🔒 홍보 집행)**만 사장님의 최종 승인을 거쳐 다음 액션으로 넘어갑니다. 나머지 접점은 손님용 화면과 매장 대시보드가 각자 알아서 다음 단계로 흘러가고, 사장님은 그 결과만 확인합니다.

## coordinator + 6개 전담 에이전트

| 에이전트 | 역할 | 주로 나타나는 화면 |
|---|---|---|
| **coordinator** | 하루 전체를 조율하고, 승인이 필요한 순간에만 사장님을 호출 | 매장 대시보드 |
| **order-payment-agent** | 주문·결제 처리, 환불·고액 결제 승인 게이트 관리 | 손님용 화면(주문) + 대시보드(승인) |
| **inventory-agent** | 재고 모니터링, 발주 초안 작성과 공급사 견적 요청 | 손님용 화면(품절 표시) + 대시보드(발주) |
| **reservation-agent** | 예약 접수와 일정 관리 | 손님용 화면(예약 확인) + 대시보드(등록) |
| **customer-service-agent** | 고객 문의·불만 응대, FAQ 자동 응답 | 손님용 화면(문의·컴플레인) + 대시보드(요약) |
| **sales-analytics-agent** | 매출 집계와 마감 리포트 | 매장 대시보드 |
| **marketing-crm-agent** | 홍보 문구·프로모션 초안, 캠페인 집행 승인 게이트 | 손님용 화면(게시 후) + 대시보드(초안·승인) |

*타임라인의 시각·수치는 마니카페 운영 시나리오를 바탕으로 한 예시입니다. 승인 임계값(15만원)과 HITL 게이트 3곳(주문·결제 / 재고·발주 / 마케팅·홍보)은 실제 운영 설계를 따릅니다.*

> **구현 가능 범위에 대한 참고**: 전화·음성 응대는 계속 사람이 수행하며, 에이전트는 웹 콘솔·디스코드로 전달된 텍스트 요청만 처리합니다(음성 인식 기능 없음). 따라서 07:00 예약처럼 실제로는 "손님용 화면"이 존재하지 않는 접점은 위 시나리오에서도 "화면 없음"으로 명시했습니다. 카카오톡은 실제로 연동되어 있지 않아 디스코드·웹 콘솔로 표기했습니다. 홍보 문구는 승인 후에도 사장님이 직접 게시해야 합니다(광고 플랫폼 자동 게시 연동 전 단계). 05:30/21:00의 야간 자동 브리핑처럼 예약 실행이 필요한 항목은 Hermes 프로필별 `cron` 기능으로 구현 가능하지만, 이 저장소에서는 아직 실제로 설정·검증되지 않았습니다.

## 웹앱에서 테스트하기

12개 타임라인 중 화면이 있는 4곳은 `webapp`(`http://localhost:19131`)의 데모 큐 버튼으로 그대로 재현할 수 있습니다 — 각 화면 하단 "데모 n/총n" 버튼을 누르면 해당 문구가 입력창에 채워집니다. 나머지 항목은 webapp 화면 자체가 없어(Discord·CLI·mock-pos 대시보드 담당) 표에 채널을 따로 표기했습니다.
