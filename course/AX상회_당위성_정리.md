# AX상회(TriAgent_SMB) 당위성 정리

**목적**: 이 앱(TriAgent_SMB / 마니카페 운영 콘솔)을 왜 만드는가에 대한 근거를 정리
**참고 자료**: 사용자 제공 인포그래픽 2장 — ①「AI 에이전트가 바꾸는 소상공인의 24시간」, ②「포항 사장님의 잃어버린 2시간을 찾아드립니다: AX 상회 'Done-for-you' 자동화 서비스」
**작성일**: 2026-09-11

> 아래 인용 수치는 참고 인포그래픽(마케팅/기획 레퍼런스 자료)에 제시된 목표·벤치마크 값이며, TriAgent_SMB 자체의 실측 결과가 아닙니다. 프로젝트의 실제 검증 결과는 4절에 별도로 구분해 인용합니다.

---

## 1. 문제 정의: 소상공인의 진짜 문제는 '도구 부재'가 아니라 '시간 부재'

두 인포그래픽이 공통으로 지적하는 핵심 전제:

- **도구는 이미 충분히 존재한다.** 배달앱, 예약앱, POS, 스프레드시트 등 소상공인은 이미 여러 디지털 도구를 도입한 상태 (인포그래픽②)
- **부족한 것은 그 도구를 운영할 '시간'이다.** (인포그래픽① 상단 메시지: "소상공인에게 부족한 것은 '도구'가 아니라 이를 운영할 '시간'입니다")
- **오퍼레이션 갭(Operation Gap)**: 도구를 도입해도 매장 운영 흐름에 맞춰 실제로 정착되지 못해 방치되는 구간이 발생 — 사장님이 셀프 세팅·학습에 쓸 시간이 없기 때문 (인포그래픽②)

즉, "AI 자동화 도구를 하나 더 파는 것"은 문제 해결이 아니라 문제의 반복이다. **세팅부터 운영, 성과 확인까지 대신 책임지는 구조**가 필요하다는 것이 두 인포그래픽의 결론이다.

---

## 2. 반복되는 손실 지점 (Before)

| 영역 | 현재 상태 (Before) |
|---|---|
| 고객 응대 | 피크타임 응대 누락, 반복적인 FAQ 답변에 시간 소모 |
| 예약 관리 | 수기 관리로 인한 노쇼(매달 약 20%) |
| 일상 업무 | 매출 정리·재고 파악·리뷰 답변 등 반복 업무에 매일 상당 시간 소요 |
| 의사결정 | POS·예약 데이터가 흩어져 있어 감(感)에 의존한 판단 |

이 네 가지는 업종(카페·식당·미용실·편의점)에 무관하게 공통으로 나타나는 손실 지점이며, 개별 앱을 따로 붙여서는 해결되지 않는다 — 각 도구가 서로 연결되지 않고 사장님이 직접 오가며 확인해야 하는 구조이기 때문이다.

---

## 3. 기존 대안의 한계: 범용 SaaS vs Done-for-you

인포그래픽②의 차별점 비교:

| | 기존 범용 SaaS | Done-for-you 자동화 대행 (AX상회) |
|---|---|---|
| 책임 소재 | 세팅·운영·활용이 전적으로 사장님 책임 | 현장 세팅·교육·튜닝·성과 리포트까지 제공자가 책임 |
| 실패 지점 | "설치했지만 안 씀" (오퍼레이션 갭) | 2주 집중 운영 기간 동안 실제 사용 로그로 튜닝 |
| 성과 확인 | 사장님이 직접 데이터를 모아 분석해야 함 | 정량적 성과 리포트를 대행사가 발행 |

범용 SaaS는 "도구"를 팔지만, 소상공인에게 필요한 것은 "그 도구가 실제로 매장에서 돌아가게 만들어주는 실행력"이다.

## 4. TriAgent_SMB가 이 문제를 기술적으로 어떻게 해결하는가

인포그래픽이 제시하는 솔루션 요소를 TriAgent_SMB의 실제 구현과 매핑하면 다음과 같다 (출처: [README.md](../README.md), [webapp/README.md](../webapp/README.md)).

| 인포그래픽②의 솔루션 요소 | TriAgent_SMB의 대응 구현 (실측 완료 항목) |
|---|---|
| 업종별 맞춤 AI 챗봇 (FAQ·예약 응대) | `customer-service-agent` — webapp 화면1에서 직결 채팅, 세션 연속성(`--resume`)까지 실제 컨테이너로 검증 |
| 예약 리마인드 및 POS 연동 (기존 POS 유지) | `reservation-agent`/`order-payment-agent` + Mock POS 연동. 실 POS 교체 없이 Mock POS로 주문·결제·재고 흐름을 먼저 검증 |
| 한눈에 보는 운영 대시보드 | webapp 화면4 — mock-pos 프록시 + Chart.js, 화면2에서 만든 주문이 즉시 반영되는 것까지 확인 |
| '실제 성과'를 책임지는 서비스 (단순 공급이 아님) | 3개 HITL 승인 게이트(프로모션 집행·대량 발주·환불)로 AI가 임의 실행하지 않고 사람이 최종 확인 — 신뢰 기반의 '대행' 구조를 기술적으로 뒷받침 |
| 오퍼레이션 갭 해소 (세팅 부담 제거) | 사장님이 도구를 배우는 대신 `coordinator`에게 자연어로 지시("아메리카노 2잔 주문 들어왔어, 결제까지 처리해줘") → 7개 전문 에이전트가 위임 처리. 학습 곡선 자체를 없애는 접근 |

**핵심 차이**: 인포그래픽②의 "Done-for-you"는 사람(전문가)이 현장 방문해 세팅·교육하는 컨설팅형 서비스 모델이지만, TriAgent_SMB는 그 역할의 상당 부분을 **대화형 AI 에이전트가 상시 대행**하도록 만드는 것을 목표로 한다. 즉, "전문가의 2주 방문 세팅"이 아니라 "AI가 매일 대신 운영"하는 형태로 같은 문제(오퍼레이션 갭)를 해결하려는 시도다.

---

## 5. 왜 지금, 왜 우리인가

- **실행 가능한 프로토타입을 이미 보유**: 7개 에이전트 프로필 전체 + coordinator 오케스트레이션 + HITL 게이트 3개를 실제 챗으로 검증 완료, webapp 4화면도 컨테이너 환경에서 end-to-end 검증 완료 — 아이디어 단계가 아니라 동작하는 시스템
- **하이퍼로컬 밀착형 시장 기회**: 인포그래픽②가 제시하듯 포항 등 지역 소상공인은 범용 SaaS의 셀프 온보딩 실패를 반복 경험 — "대신 운영해주는" 포지셔닝이 차별화 지점
- **정량적 임팩트 스토리가 이미 마련됨**: 인포그래픽이 제시한 목표 지표(업무시간 83.3% 절감, 노쇼 12%까지 개선, 챗봇 상담비용 40~70% 절감, ROI 3,600%)는 이 시스템이 검증해야 할 다음 단계의 실측 목표로 그대로 활용 가능

---

## 6. 결론

> 소상공인에게 부족한 것은 도구가 아니라 시간과 실행력이다. TriAgent_SMB는 "도구를 하나 더 주는 것"이 아니라, 사장님이 채팅 한 번으로 주문·재고·예약·고객응대·매출분석·마케팅을 맡길 수 있는 **대화형 AI 운영 대행 시스템**을 만들어, 인포그래픽이 지적한 '오퍼레이션 갭'을 사람의 방문 컨설팅이 아닌 상시 작동하는 AI 에이전트로 메우는 것을 목표로 한다.

이것이 이 앱을 만드는 당위성이다: **문제(시간 부족·오퍼레이션 갭)가 실재하고, 대안(범용 SaaS)이 구조적으로 불충분하며, 우리가 이미 그 대안의 기술적 핵심(대화형 위임 + HITL 신뢰 구조 + 검증된 프로토타입)을 갖추고 있다.**
