# 마니카페 사장님의 하루

**기존 POS로 혼자 다 하던 하루 vs. 코디네이터와 6개 에이전트가 함께하는 하루**

> 아티팩트: https://claude.ai/code/artifact/357aadf3-bb64-4d79-afed-113b11911c79

같은 카페, 같은 영업시간표 위에 두 가지 운영 방식을 겹쳐봤습니다. 왼쪽은 사장님이 카운터·발주·응대·마케팅·정산을 전부 혼자 처리하는 **기존 방식**, 오른쪽은 coordinator가 6개 전담 에이전트를 조율하고 사장님은 필요한 순간에만 확인·승인하는 **AI 에이전트 방식**입니다.

에이전트가 마음대로 돈을 쓰거나 손님에게 나가지 않습니다. 발주·결제·홍보 집행처럼 되돌리기 어려운 일은 하루 12개 접점 중 3번, 사장님의 승인을 반드시 거칩니다(HITL 게이트). 확인은 디스코드·웹 콘솔 어디서든 가능합니다.

## 한눈에 보는 숫자

| 지표 | 값 |
|---|---|
| 하루 동안의 타임라인 접점 | **12** |
| 그중 사장님 승인이 필요한 순간(HITL) | **3** |
| 동시에 움직이는 coordinator + 전담 에이전트 | **7** |

## 같은 하루, 다른 부담

기존 방식에서 사장님은 12개 접점 모두를 직접 처리해야 합니다. AI 에이전트 방식에서는 같은 12개 접점 중 9곳을 coordinator와 6개 전담 에이전트가 먼저 처리해두고, **돈이 오가거나 손님에게 나가는 3곳**만 사장님의 최종 승인을 거칩니다. 자동화가 전부가 아니라 — 결정권은 그대로 사장님에게 남기고, 그 결정에 이르기까지의 반복 노동만 덜어내는 방식입니다.

## coordinator + 6개 전담 에이전트

각자 하나의 역할만 맡아 profile 단위로 격리되어 동작합니다.

| 에이전트 | 역할 |
|---|---|
| **coordinator** | 하루 전체를 조율하고, 승인이 필요한 순간에만 사장님을 호출 |
| **order-payment-agent** | 주문·결제 처리, 환불·고액 결제 승인 게이트 관리 |
| **inventory-agent** | 재고 모니터링, 발주 초안 작성과 공급사 견적 요청 |
| **reservation-agent** | 예약 접수와 일정 관리 |
| **customer-service-agent** | 고객 문의·불만 응대, FAQ 자동 응답 |
| **sales-analytics-agent** | 매출 집계와 마감 리포트 |
| **marketing-crm-agent** | 홍보 문구·프로모션 초안, 캠페인 집행 승인 게이트 |

---

*타임라인의 시각·수치는 마니카페 운영 시나리오를 바탕으로 한 예시입니다. 승인 임계값(15만원)과 HITL 게이트 3곳(주문·결제 / 재고·발주 / 마케팅·홍보)은 실제 운영 설계를 따릅니다.*

> **구현 가능 범위에 대한 참고**: 전화·음성 응대는 계속 사람이 수행하며, 에이전트는 웹 콘솔·디스코드로 전달된 텍스트 요청만 처리합니다(음성 인식 기능 없음). 카카오톡은 실제로 연동되어 있지 않아 디스코드·웹 콘솔로 표기했습니다. 홍보 문구는 승인 후에도 사장님이 직접 게시해야 합니다(광고 플랫폼 자동 게시 연동 전 단계). 05:30/21:00의 야간 자동 브리핑처럼 예약 실행이 필요한 항목은 Hermes 프로필별 `cron` 기능으로 구현 가능하지만, 이 저장소에서는 아직 실제로 설정·검증되지 않았습니다.

## 웹앱에서 테스트하기

12개 타임라인 중 화면이 있는 4곳은 `webapp`(`http://localhost:19131`)의 데모 큐 버튼으로 그대로 재현할 수 있습니다 — 각 화면 하단 "데모 n/총n" 버튼을 누르면 해당 문구가 입력창에 채워집니다. 나머지 항목은 webapp 화면 자체가 없어(Discord·CLI·mock-pos 대시보드 담당) 표에 채널을 따로 표기했습니다.

| # | 시간 · 장면 | 테스트 방법 |
|---|---|---|
| 1 | 05:30 아침 브리핑 | webapp 없음 — Discord `#smb-ops` (설정·검증 전) |
| 2 | 06:30 재고 스냅샷 | `/inventory` — 재고 표 새로고침으로 확인 |
| 3 | 07:00 예약 응대 | `/reservations` — 데모 "07:00 전화 예약 응대" |
| 4 | 09:10 결품+발주초안 | `/inventory` — 데모 "09:10 원두 결품 발견" |
| 5 | 11:20 단체 문의 | `/support` — 데모 "11:20 단체 주문 문의" |
| 6 | 12:00 결제/환불(게이트) | `/orders` — 데모 "12:00 점심 피크 주문" 또는 "환불 요청" |
| 7 | 14:30 매출 확인 | webapp 없음 — Hermes 대시보드(`:19128`) `/chat`에서 coordinator에게 "오늘 매출 어때?" |
| 8 | 15:30 홍보초안(게이트) | webapp 없음 — Hermes 대시보드 `/chat`에서 "단호박 라떼 홍보 문구 초안 써줘" |
| 9 | 17:10 컴플레인 | `/support` — 데모 "17:10 컴플레인 응대" |
| 10 | 19:40 마감 정산 | webapp 없음 — mock-pos 대시보드(`:18080/dashboard`) + Hermes 대시보드 `/chat`에서 "마감 리포트 정리해줘" |
| 11 | 21:00 다음날 브리핑 | webapp 없음 — Discord 또는 Hermes 대시보드 `/chat` |
| 12 | 23:00 승인 확인 | webapp 없음 — Discord `#smb-ops` (설정·검증 전) |

7·8·10·11번처럼 "webapp 없음"으로 표시된 항목은 coordinator 프로필 자체는 동일하게 처리하지만, 그 화면이 webapp 5개 화면(문의·주문·재고·예약·대시보드) 어디에도 해당하지 않아 Hermes 범용 대시보드나 Discord로 확인해야 합니다. 상세 채널 매핑과 라이브 시연 절차는 [docs/21-live-demo-plan.md](../docs/21-live-demo-plan.md) 참고.
