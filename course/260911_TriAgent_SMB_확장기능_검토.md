## 1. 분류 기준

각 항목을 **영향도(고객에게 체감되는 가치)** × **소요(구현/검증에 드는 노력)** 로 나눠 우선순위를 매긴다.

- 🟢 **먼저**: 영향도 높음 + 소요 적음
- 🟡 **다음**: 영향도 높음 + 소요 큼, 또는 영향도 중간 + 소요 적음
- ⚪ **나중**: 영향도 낮음 또는 전제 조건(계약·키 확보 등)이 외부에 있음

## 4. 우선순위 요약 (다음 스프린트 후보)

1. Discord 실제 알림 발송 검증 (토큰만 설정하면 됨)

3. 예약 자동 리마인더 cron 검증

✅ **완료** (2026-09-11):
4. 예약 전용 웹 화면 추가 — 구현 완료, pytest 통과. 컨테이너 e2e 검증만 남음
6. 리뷰 자동 응답 기능 설계 — 스킬 스캐폴드까지 완료. 실제 챗 검증만 남음

🟡 **다음 단계** (신규 설계나 검증 범위가 큼, 진행 대기 중):
5. `kanban` 다단계 파이프라인 전체 실행 검증 — 실제 VPS에서 OpenAI API 호출 필요(비용 발생), 사용자 승인 대기 중

⚪ **외부 요인에 의존해 뒤로**: 실 POS 벤더 연동, `web`/`search` 툴셋, 카카오 채널 연동, 음성 인터페이스, 업종별 확장, 다중 매장 지원

## 5. 결론

현재 TriAgent_SMB의 핵심 가치(대화형 위임 + HITL 신뢰 구조)는 이미 검증됐고, 확장 방향은 크게 두 갈래다: **① 이미 설계된 것을 실제로 검증·연결하는 작업**(Discord 알림, 3개 프로필 단독 검증, cron 리마인더 — 대부분 🟢)과 **② 시장 반응(이번 영상 스토리라인이 전제한 기능들)에서 드러난 새 기능**(리뷰 응답, 예약 화면, 카카오 채널 — 대부분 🟡~⚪). 다음 스프린트는 ①부터 마무리해 "설계된 것 = 검증된 것"의 간극을 먼저 좁히는 것을 권장한다.
