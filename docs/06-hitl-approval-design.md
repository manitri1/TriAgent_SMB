# 06. HITL 승인 설계

Hermes 게이트웨이 내장 `/approve`/`/deny`는 **쉘 명령 승인**용(`approvals.mode`)이며,
"이 프로모션을 지금 발송해도 되는가" 같은 **도메인 특화 승인**과는 다른 메커니즘입니다. 이
문서는 `coordinator`가 `messaging`/`clarify` 툴셋만으로 도메인 HITL을 구현하는 방법을
정의합니다.

## 공통 흐름

```
[실행 프로필: 산출물 초안/처리 요청 생성] ──> [coordinator: Active Verification] ──> 🛑 [사장님 승인 요청]
                                                                                     │
                                                                   ┌─────────────────┴─────────────────┐
                                                                   ▼                                     ▼
                                                              (승인)                                  (반려)
                                                         다음 단계 진행                          수정 재요청 → 실행 프로필
```

## 3개 승인 지점

### 게이트 1 — 프로모션/유료 캠페인 집행

- **트리거:** `marketing-crm-agent`가 작성한 홍보 문구를 실제로 발송하거나 유료 광고를
  집행하기 전
- **승인 요청 메시지 구성:** 채널(Discord/카카오톡 등), 대상 규모, 콘텐츠 전문, (유료 광고
  시) 예산
- **승인 시:** "승인됨, 수동 집행 안내"로 응답(광고 플랫폼 API 실연동 전까지는 자동 집행
  불가 — [07장](07-roadmap.md))
- **반려 시:** 반려 사유를 `marketing-crm-agent`에게 전달해 문구/예산 재조정 요청

### 게이트 2 — 재고 대량 발주 확정

- **트리거:** `inventory-agent`가 산출한 발주 금액이 `USER.md`에 정의된 임계치를 넘을 때
- **승인 요청 메시지 구성:** 품목, 현재 재고, 발주 수량·예상 금액, 발주처(있는 경우)
- **승인 시:** `inventory-agent`에게 "승인됨" 상태로 전달, 발주 확정은 여전히 사장님이
  수동으로 처리(실 발주 시스템 연동 전까지는 자동 확정 불가)
- **반려 시:** 반려 사유를 `inventory-agent`에게 전달해 수량 재조정 요청

### 게이트 3 — 결제 환불/주문 취소 처리

- **트리거:** `order-payment-agent`가 결제 환불이나 주문 취소를 처리하기 전
- **승인 요청 메시지 구성:** 대상 주문, 환불/취소 금액, 사유
- **승인 시:** `order-payment-agent`가 Mock POS `POST /payments/{payment_id}/refund`를
  호출해 실제로 환불을 처리한다(결제/주문이 `REFUNDED`로 전환되고 재고가 원상 복구됨).
  Mock POS 단계이므로 실제 결제 게이트웨이 환불은 여전히 실 POS 연동 후에나 가능하다
  ([07장](07-roadmap.md))
- **반려 시:** 반려 사유를 `order-payment-agent`에게 전달해 재확인 요청

## 대화 프로토콜 (공통)

1. 승인 요청 메시지는 항상 "무엇을/왜/영향"을 한 메시지 안에 명확히 담는다(요약하지 않고
   핵심 정보 전문을 포함).
2. `clarify` 응답을 기다리는 동안 같은 대상에 대한 다른 작업을 병행하지 않는다.
3. 모호한 응답("나중에", "글쎄")은 승인도 반려도 아니다 — 다시 구체적으로 확인한다.
4. 모든 승인/반려는 날짜와 함께 `coordinator/MEMORY.md`에 기록한다.

> 게이트웨이의 `/approve`·`/deny`(`approvals.mode`)와 이 앱 레벨 메시징 기반 승인을 혼동하지
> 않습니다 — 전자는 쉘 명령 실행 승인이고, 후자는 이 문서가 정의하는 도메인 승인입니다.

## HITL 게이트로 두지 않은 것

- **예약 생성/취소**: 고객이 직접 요청한 사안이고 금액·계약 리스크가 낮아 게이트 대상에서
  제외했습니다. `reservation-agent`가 즉시 처리합니다.
- **소액 재고 발주**(`USER.md` 임계치 이하): 매일 반복되는 저위험 운영이라 게이트 없이
  진행합니다.
- **고객 불만 접수**: 접수 자체는 즉시 하되, 심각도가 높은 건은 coordinator에게 "보고"하는
  것으로 충분하며 승인을 기다릴 필요는 없다고 판단했습니다.

이 판단은 SMB 도메인(단일 의사결정자=사장님, 상대적으로 낮은 건당 금액)에 맞춘 것으로,
형제 프로젝트 `TriAgent_MICE`(다수 이해관계자, 계약 단위 고액 거래)의 7개 게이트보다 적은
3개로 시작합니다. 운영하며 필요하면 게이트를 추가할 수 있습니다.
